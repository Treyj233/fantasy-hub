# Fantasy Hub audit and cleanup

## Scope and limits

Reviewed shared dashboard state, news refreshes, Vegas projection refreshes, weekly recap/welcome coordination, overflow handling, error recovery, and existing layout tests. Ran the app-wide build, test suite, and app lint. Inspected the live signed-in entry flow and News & Notes in desktop and 390 × 844 browser viewports.

This is a verified cleanup pass, not a claim that every feature or device has been exhaustively tested. Native iPhone/iPad safe areas, live game-day load/temperature, payments, generated PDFs, and every league/scoring configuration still require dedicated verification. Browser observations were of the current live release, not the unpublished changes below.

## Changes made

- **News refresh reliability:** failures no longer display “Updated”; cached articles remain available with an explicit stale-feed message. Newer requests supersede older responses. Requests have a 15-second timeout, cancel when hidden/unmounted, and clear feedback timers.
- **Background work:** News uses visibility-aware polling instead of an unconditional interval. Vegas projection refreshes use the existing non-overlapping visible poller and bounded network requests. Existing cadence and projection formulas are unchanged.
- **News presentation:** “NEW” means published within the last hour, rather than simply first in the list. Snow-tagged stories receive blue accents in both themes. Filter selection is announced with aria-pressed; keyboard controls have visible focus outlines. Long player chips/headings wrap; reporter attribution is grouped; the load-more label shows the actual number available.
- **Week rollover:** the live audit showed a Week 1 welcome over a Week 2 dashboard. The welcome now waits for the current season schedule, is gated by both selected/current week, and cannot suppress the weekly recap after it becomes irrelevant.
- **Regression coverage:** added five request behavior tests for success, malformed/error responses, stale-response rejection, cancellation, and abort propagation. Updated the news label and welcome guard assertions.

The React best-practices review informed request lifecycle cleanup, shared polling reuse, and deriving welcome visibility from current state rather than introducing another synchronized state variable.

## Verification

- Production build: passed.
- Full test suite: **445 tests; 382 passed; 63 failed**. Baseline was **440 tests; 377 passed; 63 failed**. No new failing test names remain.
- Existing source-pattern tests cover several retired layouts and behaviors; failures need individual triage rather than blanket deletion or assertion changes.
- App lint baseline: 37 errors, principally existing effect-state patterns, explicit any types, and native navigation/script checks. This cleanup does not resolve that backlog.
- No scoring, trade valuation, membership permissions, account linking, or social posting logic changed.
- Preserved unrelated iOS project edits and existing local artifacts.
- **Not published.**

## Remaining priorities

1. Triage the 63 existing failures into obsolete assertions versus functional defects, then replace brittle source-regex checks with interaction/behavior tests where feasible.
2. Review the existing effect-driven state paths in the large dashboard component, especially account/league/projection switching. Avoid broad refactors without end-to-end coverage.
3. Test modal focus, scrolling, safe areas, and orientation in actual iPhone/iPad builds; desktop responsive emulation is not sufficient proof.
4. Measure sustained game-day CPU/network/render behavior before claiming any thermal or battery improvement. The polling changes reduce unnecessary work but are not a device benchmark.
5. News content still warrants separate data-quality review: the live feed included duplicate-looking related names and awkwardly split next-step text. Do not infer identity corrections from display names alone.
